# 乘乘熱氣球｜九九乘法嘉年華

給小朋友背熟九九乘法表的網頁小遊戲，主題是熱氣球嘉年華。全部程式都在一個 `index.html` 裡，不需要安裝或編譯。

## 功能

- **主視覺是鹿野高台的大草原**：整個畫面後面固定著一片手繪 SVG 的山坡草地 ——
  上面是淡藍天空，下面是**五層山**：每一層都是**一座一座分開的圓頂山**（不是連成一條的波浪），
  各自有高有低、右半邊壓一道暗色當山脊的陰影；最遠的一層最高、偏藍，越靠近越低越綠。
  山的 viewBox 用 420 寬（不是 1200），橫向才不會被 `preserveAspectRatio="none"` 壓成細長條。
  天上還有六顆遠方的小熱氣球，**從山的高度那邊起飛、一路慢慢升空**（68～112 秒升完一趟，
  淡入淡出後重來）。
  `body` 背景設成透明，草原才看得到
- **明亮淡彩配色**：主色霧感灰藍 `#7FA0B6`、底色淡奶油黃 `#FDFAF0`、輔色燕麥米 `#E0D4C2`、
  點綴淡鼠尾草綠 `#AEBDA4`；比前一版再亮一階，但沒有變鮮豔。大面積填色另外用提亮一階的淺色版。
  視覺語彙是**剪紙拼貼 + 絹印**：卡片沒有外框線，邊緣是 SVG 位移濾鏡做出來的手撕邊，
  底下墊一層偏移的燕麥米疊印；全站覆蓋一層紙張顆粒；標題「乘乘熱氣球」用偏移 4px 的灰藍 multiply 做套色錯位。
  **畫面固定白天模式**，不會跟著手機或電腦的深色模式變暗（要暗版的話在 `<html>` 加 `data-theme="dark"`）
- **慶典三角旗**：六色輪播、方旗和三角旗交錯、繩結上還有小圓球。
  **兩種旗子都是圓弧的**：尖旗的兩邊往外鼓、方旗的底收成半圓，沒有銳利的直角
- **主視覺 icon**：一顆寫著 **9×9** 的熱氣球，用的就是全站同一套顏色。
  分頁上的小圖示直接畫成 SVG 寫進 `data:` URI 掛在 `<link rel="icon">`，不用外部檔案，單檔離線也看得到；
  另有 `<meta name="theme-color">` 讓手機瀏覽器的上緣跟著天空色。
  **加到主畫面**的圖示 iOS 只吃 PNG，所以另外附了 `icon-180.png`（apple-touch-icon）和
  `icon-192.png` / `icon-512.png` + `manifest.webmanifest`（Android 用）。
  四張圖都是從 `icon.svg` 這張原稿輸出的，改圖只要改 `icon.svg` 再重出一次。
  加到主畫面後會用**獨立視窗**開啟（沒有網址列），跟一般 app 一樣
- **首頁是一片熱氣球**：六個玩法六顆球，慢慢上下漂浮（節奏各自錯開），
  手機兩個一排、平板和電腦三個一排，填滿畫面。
  氣球是**手繪 SVG**：球身上半部用貝茲近似正圓（0.5523 係數）、下半部收成短頸，
  加裙帶、細網索和小藤籃；布面有六種花紋（直條／格紋／鋸齒／波浪／圓點／葉形）。
  遊戲名稱做成小標籤貼在球的右上角、左上右下傾斜，玩法符號直接印在球身上。
  **球身有四種做法**，不會全部都是直條紋：`gore`（直的布片）、`band`（橫條紋）、
  `half`（上下兩色、中間一道波浪）、`solid`（單色＋柔和陰影），
  每顆最多再疊一種花紋（圓點／格紋／鋸齒），一顆球只有一個重點。
  **球身的顏色是隨機的淡彩色**（八組色票，每次進首頁重洗），
  難易分別看的是**標籤的顏色**：前三顆入門的「乘法翻翻樂、這是幾乘幾？、尋寶遊戲」
  標籤是**淡鼠尾草綠**、前面有 🔰 記號（手繪的若葉盾牌，不是 emoji）；
  後三顆「配對消消樂、彩虹貪食蛇、乘法實戰家」標籤是**霧感灰藍**。
  **每次進主畫面**（剛開遊戲、按標題列的「乘乘熱氣球」、任何遊戲結束回首頁）
  畫面上的東西會**由上而下一個接一個淡入上飄**：
  旗幟 → 大標 → 副標 → 換人 → 連續天數那排 →（有的話才有的小提示）→ 六顆氣球，
  每個 1.44 秒、相鄰差 0.08 秒；**兩個攤子和轉蛋機再晚 0.5 秒**才進來。
  **不動的三個**：置頂那排（在 `#view` 外面）、陪我玩的小夥伴（掛在 `body` 上）、
  以及首頁以外的所有畫面。順序由 `riseHome()` 依 `querySelectorAll` 的畫面順序填 `--ed`，
  不寫死在 HTML 裡。氣球的進場掛在外層按鈕、原本的上下飄浮掛在裡面的球身，
  兩層分開才不會互相蓋掉。系統開「減少動態」時整個不做
- **首頁的小提示**：只在三種狀況出現——第一次玩、金幣夠轉蛋了、貼紙全收完了。
  **平常不出現**（本來有一句「完成下面攤子的任務就能拿金幣…」，拿掉了）：
  攤子和氣球自己說得夠清楚，畫面留白比較好看
- **說明小幫手**：**標題列左邊**（logo 旁邊）有一張黃色的「我教你玩」小標籤，
  上面是小熊坐小熱氣球，點一下就叫出「怎麼玩？」的說明。
  本來是漂浮在畫面上的，但是會擋到遊戲按鈕，所以收進標題列；
  窄螢幕（≤372px）只留小熊氣球，字收起來；
  每個畫面上方也有一條小提示；第一次建立玩家時會自動跳出教學
- **小夥伴陪你玩**：轉蛋收集到的貼紙，點開可以按「陪我玩」叫它出來。
  **稀有和閃亮的夥伴身上會罩一層會呼吸的淡金光**（閃亮的更亮更大），普通的沒有。
  出場時**不帶貼紙圓底、不帶白框**，就是那隻動物／點心本身在飄（只留一層柔和陰影），
  上下輕輕浮動、不左右傾斜。它會在**所有畫面上隨機漂移**（上下左右），不時冒出鼓勵的話
  （「慢慢來，不用急」「你剛剛沒有放棄」「六七⋯⋯四十二！」…共 20 句，裝在**圓形的對話框**裡，
  下面還有兩顆小泡泡指向牠）和閃亮小圖案。
  這些話一律走**成長型思維**：誇努力、方法和「願意再試一次」，不誇聰明也不誇結果，
  所以沒有「你好棒」「好厲害」這種只看表現的句子。
  20 句裡有 8 句是**純閒聊**（「不想睡覺怎麼辦？」「要不要喝口水？」「肚子有點餓了」…）——
  一隻一直在鼓勵你的動物像大人，偶爾講廢話的才像朋友。它是 `pointer-events:none`，不會擋到任何按鈕；
  再點一次貼紙按「回去休息」就收回。一次只能帶一隻
- **訪客模式**：入口頁下面有一區「用訪客模式玩」，不用名字、不用挑頭貼就能玩所有遊戲，
  旁邊寫清楚**沒有金幣可以蒐集**、貼紙和紀錄也不會留下來；
  首頁會掛一條同樣的提醒，按「取名字」隨時轉成正式玩家（進度會接過去）。
  訪客模式下 `save()` 直接 return，不寫 localStorage 也不同步雲端
- **右上角的金幣可以點**：點下去會說明那是什麼、怎麼拿、現在有幾枚。
  **沒有星星制度**，全站只有金幣一種獎勵
- **全站標注音**：整個畫面的中文都標了注音，右上角的「**ㄅ／國**」按鈕可以隨時切換（預設是注音），
  現在是哪一種、那一邊的字就是深色的。
  做法不是自己排版，而是換成**源泉注音圓體**（`BpmfGenSenRounded`）—— 注音是直接畫在每個字裡面的，
  所以只要換 `font-family` 就有，不用在 HTML 裡加任何標記。漢字會變寬 1.5 倍，
  所以不能換行的地方（大標題、氣球標籤、攤位屋簷）在開注音時會換一組尺寸，
  但是**刻意跟沒注音時差不多大**，不是一律縮小；熱氣球上的遊戲標題還特別做得比下面的說明字大。
  數字和英文還是走原本的 Fredoka（`unicode-range` 限定只有漢字用注音字型）。
  **多音字**用注音 IVS 處理：在字後面補一個看不見的「異體字選擇子」（U+E01E0~5）去挑正確的讀音，
  例如「不會」的「不」要唸 ㄅㄨˊ 而不是字型預設的 ㄅㄨˋ。
  哪些字要補、補哪一個，是 `make-font.py` 拿 `zhuyin.txt` 跟字型對出來的（目前 3 個字、12 個詞）
- **全站不用 emoji**：介面符號全部是手繪的 icon 插畫風 SVG（金幣、星星、愛心、旗子、放大鏡、
  方向鍵、獎盃……）。文字裡寫的 🔰 也會被 `mk()` 換成手繪的若葉盾牌 SVG。
  只有收藏用的 63 張貼紙和尋寶場景、數數物件還是手繪 SVG 插畫
- **這是幾乘幾？** 🍡🔰（🔰 三顆的第二顆）：還不會乘法的第一站。畫面畫出「幾排、每排幾個」（🍡🍡🍡🍡🍡 四排），
  問「這是幾乘幾呢？」，兩個格子標著**「每排幾個」×「有幾排」**，點數字填進去，
  答對就唸出口訣「五四二十」（唸法和速度跟翻翻樂完全一樣）。
  **一格一格驗**：「每排幾個」填錯就停在那一格，直接顯示錯誤，填對了才輪到「有幾排」。
  提示按鈕放在標題旁邊，**跟著現在在填哪一格走**：還在填「每排幾個」時，按幾次都是
  在數數框最上面冒出紅字「↓ 這一排有 5 個喔！」並把第一排框成紅色；
  填到「有幾排」時按提示，才換成「↓ 總共有 4 排喔！」並把每一排的號碼用紅色放大跳出來數。
  **填對一格提示就自動收起來**，要再按才會出現下一段。
  每一段都會唸出來。提示字是**獨立一行放在框的最上面**，下面的圖案不會被推歪。
  題目的提示和說明都放在數數的框**上面**，眼睛不用一直上下跑。
  **順序照課本**（被乘數 × 乘數＝每排幾個 × 有幾排）：4 排、每排 5 個只能寫 5 × 4。
  前三題是小數字，後面才到 9。一回 8 題
- **乘法翻翻樂** 🔰：選一張乘法表後是 9 張蓋著的卡，點一下翻面看答案並同時唸出口訣，
  翻開的卡片上還會**隨機冒出一個閃亮小圖案**（八種手繪圖案隨機配色，每翻一次都不一樣）。
  有「全部蓋起來 / 自動播放」。翻幾次都可以，也不會動到小綠點。
  卡片正上方有一條黃色提示「**先想想看，再翻答案**」，字比一般說明大一級，
  提醒孩子別把翻翻樂玩成只看答案
- **乘法實戰家**：每答完一題（答對或答錯）都會**把算式唸出來**，2×2 就唸「二二得四」。
  原本的「練習闖關」和「限時挑戰」合併成一個入口。進去最上面是
  **比快挑戰（60 秒）**，下面是 12 關**全部直接可以玩、不用解鎖**。
  第 1~8 關是 2~9 的乘法，第 9~12 關是混合挑戰 ×2、弱點挑戰、👑 大魔王（15 題）。
  上方可以切換「自己打數字 / 選答案」；每關 10 題，第一次就答對八成即過關，不熟的題目同一回合會再出現一次。
  （**全站玩家看得到的文字一律寫「不熟」不寫「答錯」**，跟「慢慢來」的語氣一致）
  卡片上會顯示過關狀態和這張乘法表的熟練度小綠點，
  **還沒過關的關卡是暖黃底**、已經過關的是淡綠底、大魔王是淡紫底——
  第一次過關才有比較多金幣，所以還沒過的那幾關要最顯眼。
  首次通關送 1 枚金幣（全對再加 1 枚），**每天最多領 2 枚**；
  重玩通關也有 1 枚，每天最多 1 枚。轉一次扭蛋要 **3 枚金幣**，金幣不會一下就滿出來
- **配對消消樂** 🔰（簡單那一級）：選完難度就直接進遊戲（原本的「找不同」已經拿掉）。
  牌面上都是算式，**答案一樣的兩張配成一對**（說明舉的例子是 4×1 和 2×2 都是 4），
  配對成功會把兩句口訣都唸一次、**每一組亮不同的顏色**（八組八色），
  唸完**卡片就縮小消失**；答案（「3×2 和 2×3 都是 6！」）用大字顯示在標題正下方。每一局**一半是「不同寫法」的配對**（12 = 2×6 = 3×4），
  一半是交換律（3×4 / 4×3）。**「寫法完全不同」的那一半是固定的九組**，不是算出來的：
  4＝1×4/2×2、6＝1×6/2×3、8＝1×8/2×4、9＝1×9/3×3、12＝2×6/3×4、
  16＝2×8/4×4、18＝2×9/3×6、24＝3×8/4×6、36＝4×9/6×6；
  每一局都會從裡面抽出**剛好一半**的組數（難度放得下的才會出現）。
  同一局裡的答案不會重複，所以不會有配錯組的問題。
  三個難度：🔰 簡單（4 組・數字 1~6）、普通（6 組・1~9）、挑戰（8 組・1~9）
- **尋寶遊戲（找數字）** 🔰：像 Mystery Numbers 那種「找數字」的找找看遊戲。
  選 2 的乘法，畫面會畫出一個完整的卡通場景（目前 17 個，見下面「場景」那段），
  2、4、6……18 這九個答案就**用該表面的顏色**寫在場景上 —— 牆上、窗玻璃、棉被、地毯、樹冠、海浪、磁磚、火山……
  半透明、歪斜、還會被前面的東西擋住一半，另外再混 4~6 個不是答案的數字。
  題目**隨機出**（不照 1、2、3 的順序），找到正確答案點它一下，數字會被圈起來並唸出口訣。
  九個都找到就收進**畫廊**。找錯會提示（第三次直接指出答案），**提示鈕就放在題目旁邊**
- **場景是怎麼來的**：全部是寫在 `index.html` 裡的**手繪 SVG**（沒有外部圖片 —— 網路上的場景圖有版權問題，
  而且這個遊戲要能單檔離線執行、CSP 也擋住了外連圖片）。
  每個場景自己帶著「可以藏數字的位置 + 那個表面的顏色」和「道具擺放點」，
  手繪道具會擺在床上、桌上、地毯上、沙灘上，位置和數量每張都隨機，所以同一個場景也不會長得一樣
- **畫廊**：完成的畫都收在這裡（答案圈著，像破關後的畫面），點開可以看大圖。
  存檔只記「乘法表 + 場景 + 亂數種子 + 日期」，畫面再用種子重算，所以每張畫永遠長得一模一樣
- **彩虹貪食蛇**：乘法版貪食蛇，蛇本身就是一條彩虹。上面出一題，盤面上的數字都寫在**蘋果**上
  （一顆是正確答案，其他是干擾；蘋果是 CSS 裡的手繪 SVG，數字大小會跟著格子縮放），
  控制蛇去吃正確的那一顆，吃對就長大一節。
  **蛇的顏色是固定的**：紅色永遠是頭，往後照紅橙黃綠藍靛紫排下去，超過七節就再循環一次。
  吃滿 7 個完成一條彩虹，**吃到 14 個（兩條彩虹）就直接放煙火過關**。
  三個難度並排、說明各兩行：**🔰 散步**（自己慢慢走／照順序出題）、
  **快走**（蛇蛇會動喔／照順序出題）、**賽跑**（蛇蛇跑更快了／隨機出題）：
  🔰 散步（照順序出題＋點一下走一格，5 顆心、9×9）→
  慢跑（照順序＋自動前進 850ms，4 顆心、11×11）→
  衝刺（隨機出題＋自動前進 600ms，每條彩虹加速到最快 450ms，3 顆心、11×11）。
  對小孩友善的規則：撞牆會從另一邊鑽出來、打結只會縮短不會結束、吃錯只扣一顆愛心且題目保留讓他再算一次。
  **愛心扣完就是這一局結束**（不扣金幣、不扣紀錄，結果畫面照樣寫「你剛剛很認真！」），
  但**不放煙火也不放彩帶** —— 那不是過關，慶祝反而怪（`r.snake && !r.win` 不跑慶祝特效）。
  操控：**直接點蛇頭前面那一格就會轉過去**（盤面四邊是接起來的，會自己挑近路），
  也可以滑動盤面、或用下面的方向鍵（可以隱藏），電腦支援方向鍵／WASD／空白鍵暫停
- **比快挑戰**：併在「乘法實戰家」裡，60 秒內盡量答對，記錄最佳成績。
  時間條一開始就是全滿的，開始後才往下減
- **備份紀錄**：紀錄存在瀏覽器的 localStorage，**更新程式不會清掉**（同一個網域就是同一份），
  但手機系統可能會清（iOS Safari 超過約 7 天沒進來就會把網站資料整個刪掉）。
  所以做了三道保險：①同一個瀏覽器裡另外寫一份**備份槽**（`...-bak`），主檔壞掉或被清掉會自動救回來；
  ②挑戰者頁面可以把紀錄**存成 .json 檔**，換手機、重灌都還原得回來；
  ③載入時呼叫 `navigator.storage.persist()` 請瀏覽器不要自動清。
  iOS 要「加入主畫面」從圖示進來玩才算安裝版、資料才不會被 7 天規則清掉。
  **說明視窗多了一個 `note` 欄位**：小孩看的編號步驟不動，下面另外加一塊灰底小字給大人看，
  首頁的「怎麼玩？」和「挑戰者」的說明都寫了紀錄會不見、要去哪裡備份；取名字那一頁也補了一行
- **挑戰者**：可以建立多位挑戰者（最多 6 位），各自有名字和頭貼；金幣、貼紙、熟練度和每日任務都分開記錄，隨時可以切換。
  頭貼可以選 6 顆不同花紋的熱氣球，**也可以用自己轉蛋收集到的任何一張貼紙**
  （轉蛋機點開貼紙按「當我的頭像」，或改名字的視窗裡直接挑）。
  貼紙頭貼只出現在**那一位挑戰者自己的**改名字視窗裡 —— 新增挑戰者時還沒有收藏，所以只看得到熱氣球
- **每日任務攤子**：**兩個**祭典攤販**各自分離，固定在畫面最下方**，站在草坡上，
  每一攤都描了一圈白框，像貼紙一樣；彼此隔開不相鄰，下方留著「利利寫生活製作」的位置不會被蓋住。
  一個攤位就是一種難度：**初級任務 / 超級任務**，
  名字寫在攤位的**屋簷**上，桌子上只寫進度（`2/3`），點一下才展開那一攤的三個任務
  —— 說明就是那三行任務本身，不另外寫一段介紹。

- **我的轉蛋機**：做成一台漂浮、微微發光的手繪轉蛋機（一樣描了白框），
  **固定在畫面右上角**，點一下就打開。
  **63 張貼紙**：六類各 10 張（6 普通／3 稀有／1 閃亮）＋最後的「台灣之最」3 張。不重複抽取。**一次要 3 枚金幣**，

- **收藏格子左右分區**：五欄的格子裡，**左邊三欄放普通、右邊兩欄放稀有和閃亮**，

- **還沒收集到的格子會先透露稀有度**：稀有款是藍色虛線框、閃亮款是金色虛線框還會微微轉光，
  底下的字寫「稀有款」「閃亮款」而不是「？？？」，讓小孩知道那一格值得期待
- 答對動畫、彩紙、連擊計數；**每答對一題都會響一組「叮－叮－叮」的三連音**，連擊越多音越高。
  **過關的慶祝分兩種**：🔰 的三個遊戲灑一片閃亮（配清脆的高音），
  後面三個難的遊戲放彩帶（配號角聲）
- **說明文字全部改寫成 7 歲小孩聽得懂的短句**（例如「這個遊戲怎麼玩」→「怎麼玩？」）。
  首頁的「怎麼玩？」只有三句：剛開始學乘法先玩 🔰 → 闖關遊戲或完成攤子任務賺金幣 →
  金幣可以玩轉蛋，有 63 種等你蒐集
- **每個遊戲離開時都有三個選擇**：繼續玩 / 退回它自己的挑選畫面 / 回首頁。
  中間那顆按鈕會依遊戲換字：實戰家和比快挑戰寫「回關卡」、貪食蛇和配對消消樂寫「回選難度」、
  尋寶遊戲和翻翻樂寫「回選乘法表」。結算畫面也有同一顆
- **錯了一律柔和提醒**：全站的錯誤訊息都用「慢慢來，…」開頭，不寫「不對」「答錯了」
- **連續天數**：首頁顯示「連續 N 天」，每天玩完任何一個遊戲就 +1。
  **斷掉的時候不顯示 0**，而是換成「歡迎回來」（手繪小禮炮）；還沒玩過的新挑戰者顯示「今天開始」。
  天數本身照舊從 1 重新數起，只是不要用一個 0 去罰那個隔了幾天才回來的孩子
- **小綠點（熟練度）**：每張乘法表旁邊有 9 顆點，對應 1~9。同一題**連續答對 3 次**才會變成
  亮綠點，答對過但還沒連三次是**半亮**的；答錯就把連續次數歸零。
  **7×8 和 8×7 分開算**（`key(a,b)` 就是 `a+'x'+b`）—— 學校教的是「7 個 8」和「8 個 7」，
  意義不一樣，所以兩張表的點各亮各的。2026-11-24 以前是合併的，舊存檔由 `fixPlayer()` 的
  `fsplit` 旗標一次性把 `a×b` 的成績複製一份給 `b×a`，所以小孩的綠點不會倒退。
  只有「第一次就答對、而且沒看提示」才算數；**翻翻樂沒有作答**，所以翻再多次點也不會亮
- **選了幾的乘法，那一張表就固定當被乘數**：選 5 的乘法，題目全部是 `5 × b`，
  不會跑出 `1 × 5`（關卡、尋寶、貪食蛇都一樣）
- **口訣照畫面上的順序唸**：卡片寫 8×1 就唸「八一得八」，不會自己調成「一八得八」；
  題目寫 9×3 就唸「九三二十七」。答案剛好是 10 的唸「二五**得十**」，不唸「二五一十」

## 聲音和陪玩夥伴

**答錯的音效刻意比答對小聲。** 原本答錯用方波（240Hz→180Hz），答對用三角波；
同樣的振幅下方波的 RMS 是峰值本身、三角波只有 0.577 倍，等於答錯白白大了快 5 dB，
再加上低頻方波本來就刺耳。現在答錯改成正弦波、音高拉高（330Hz→262Hz）、
音量壓到 0.035（答對 0.052），聽得到但不像在罵人。`r3.html` 有一條測試在盯這個比例。

**陪我玩的小夥伴**只有稀有和閃亮款有金光。光圈一路往內收：inset −24%／−32% → −9%／−14% →
現在的 **−5%／−8%**（真機上看稀有款還是偏大，閃亮款會更大，所以兩個一起縮），
漸層的外緣也一起收快（78%→72%、77%→70%）；呼吸維持 3.6s/scale 0.9→1.14 不動，那個節奏是對的。
說的話分成兩份、**一句鼓勵一句閒聊輪流出現**（`buddyLine()`，同一份裡面才是隨機挑）：

| | 幾句 | 寫什麼 |
|---|---|---|
| `BUDDY_CARE`（鼓勵句）| 11 | 肯定「他剛剛做了什麼」（努力、沒放棄、自己想出來），把卡住講成一件正常的事 |
| `BUDDY_FUN`（趣味句）| 9 | 純粹好玩的閒聊，讓它像個會分心的朋友，不是一直在鼓勵的大人 |

全部都是鼓勵，它就變成一直在說教的大人；全部都是閒聊，又少了陪伴的感覺，所以要輪流。
鼓勵句一律**不預言結果**（「下次就會答對了」會變成壓力），不出現「錯」字，
不用六歲讀不懂的詞，意思重複的只留一句。24 句 → 20 句（11 ＋ 9）。
句子是使用者自己改的，有幾句（「我最喜歡星期五！」「咻～鬼抓人！」「歐拉歐拉」）
刻意跟乘法完全無關——那正是重點，它是朋友不是老師。

**點一下小夥伴，它就說話**（`data-act="btalk"`）：馬上冒一句話、灑三顆閃亮、響一聲 `sfx.tap()`。
原本它只會自己每隔幾次說一句，小孩點它完全沒反應。
只有**貼紙本體**吃手指（`.bart{pointer-events:auto}`），說話泡泡不吃
——泡泡會飄到別的按鈕上面，吃了手指就會擋住下面的東西。

## 怎麼把更新送到小孩的裝置上

iPhone 用 Safari「加入主畫面」之後，那一頁會被留在快取裡很久
（GitHub Pages 送的是 `cache-control: max-age=600`，但 standalone 模式可以更久），
所以**推上去的更新常常傳不過去**。原本他是在按左上角那顆氣球當「重新整理」，但那只是換頁。

現在的作法（`updCheck()`）：跟伺服器要一次這一頁的 **`Last-Modified`**
（`fetch(..., {method:'HEAD', cache:'no-store'})`，只拿表頭、不下載 400KB 的內容），
比手上這一份（`document.lastModified`）新兩秒以上，就把標題列裡的橫幅打開：

> 遊戲更新了！　[換成新的]

- **不用自己維護版本號** —— 推上去 GitHub Pages 就會換 `Last-Modified`，自動被看到。
- 什麼時候問：**開啟後三秒**（不跟第一次繪製搶）、**每次回到這個分頁**（`visibilitychange`）、
  還有**按左上角那顆氣球的時候**（`data-act="logo"`，他本來就是把它當重新整理在按的）。
  五分鐘內不重複問，`force` 的那幾次才跳過節流。
- 橫幅掛在 `.topbar` **裡面**，不是浮在上面。標題列是 sticky，所以它會跟著黏住，
  而且是正常的流排版，不會蓋到下面的內容。
- 「換成新的」做的是 `location.replace(location.pathname+'?v='+Date.now())`
  —— **一定要換網址**，`location.reload()` 在 Safari 還是會拿到快取裡的舊檔。
- `file://` 下（測試矩陣就是）不會連網也不會開橫幅。`r8.html` 盯著這整套。

## 注音字型

用的是 ButTaiwan 的**源泉注音圓體**（`BpmfGenSenRounded`，SIL OFL 1.1），
授權和著作權聲明放在 `fonts/OFL.txt`、`fonts/NOTICE.txt`。

原始字型一個字重就有 8 MB，所以 repo 裡放的是**切過子集的版本**，只留遊戲裡真的會出現的字：
`fonts/bpmf-gensen-m.woff2`（Medium，內文用）和 `fonts/bpmf-gensen-b.woff2`（Bold，粗體用），
各約 226 KB、1076 字。用 Medium 當內文是因為 Regular 的注音在小字級下太細，看不清楚。
不在子集裡的字（例如玩家自己打的名字）會掉回原本的粉圓，沒有注音但不會破版。

### 改了 `zhuyin.txt` 之後怎麼重新產生

`zhuyin.txt` 現在只拿來「挑讀音」——注音長什麼樣子是字型決定的，
這張表只負責指出「哪些字的預設讀音不對」。改完要跑：

```sh
pip install fonttools brotli
# 到 https://github.com/ButTaiwan/bpmfvs/releases 下載 BpmfGenSenRounded.zip 解開
python3 make-font.py ~/Downloads/BpmfGenSenRounded-M.ttf ~/Downloads/BpmfGenSenRounded-B.ttf
```

它會重新對照、把選擇子表寫進 `index.html` 的 `ZY-TABLE` 區塊，並重新輸出 woff2。
對不上的地方會印出來（目前只有「什」——ㄕㄜˊ 這個音字型沒有，所以「什麼」的「什」不標注音）。

## 製作

頁面最下面是三段，用「｜」隔開：

```
利利寫生活 製作｜關於遊戲｜最後更新：2026.11.24
```

- **利利寫生活** —— **純文字，不是連結**。IG 連結只放在「關於遊戲」那一頁裡面
  （2026-11-25 改的：頁尾兩顆連結太吵，而且小孩誤觸會直接跳出遊戲到 Instagram）。
- **關於遊戲** —— 頁尾唯一能點的東西，連到站內的「給大人的說明」那一頁
  （`VIEWS.about`，`data-act="about"`）。它是 `<button class="lk">` 不是 `<a>`，
  因為那是站內換頁、不是外部連結。
- **最後更新** —— 日期直接讀 `document.lastModified`（也就是 `index.html` 的 Last-Modified），
  所以每次推上去就會自己更新，不用手動維護。

原本那句「意見回饋請私訊留言」拿掉了：同樣的意思在「關於遊戲」那一頁講得更完整，
頁尾只留三個入口，比較不吵。

「｜」是掛在**前一段的尾巴**（`<span class="sep">`），不是獨立一格——
頁尾會換行（320px 就變兩行），分隔線獨立一格的話會變成下一行的開頭，很醜。

這一行**不上注音**（`.credit` 標了 `nozy`，那是寫給大人看的）、字級 12.5px，
**緊貼畫面底部**。高度不再用斷點硬寫：`fitCredit()` 量它實際多高（再加 6px 呼吸），
填進 `--credh`，攤位就剛好停在它正上方——換寬度變成兩行三行都會自己跟上。
字縮小了，但兩個連結都用 `::after` 把可以按的範圍上下各往外撐 9px，手指還是按得到。
`foot.html` 盯著高度和按壓範圍，`r7.html` 盯著文字、連結和分隔線的位置。

## 執行

部署到 GitHub Pages：推到 repo 後，在 Settings → Pages 選擇從 `main` 分支根目錄發布。

## 綜合挑戰

「乘法翻翻樂」和「尋寶遊戲」的選表畫面，除了 2~9 之外多一顆紫色的**綜合挑戰**：
九題從 **2~9 的乘法裡隨機抽**，不重複（交換律算同一題，所以不會同時出現 3×7 和 7×3），
也不會出現 1 的乘法。

尋寶遊戲的綜合挑戰，九個答案是由**那張畫自己的種子**決定的
（`artPairs()`，種子是 `場景編號 + 畫作編號`），所以同一張畫收進畫廊之後再打開，
藏的還是同樣九題。畫廊和結算畫面會寫「綜合挑戰」而不是「N 的乘法」。
存檔裡畫作的 `t` 欄位用 **0 代表綜合挑戰**。

## 每天的金幣有上限

六個攤子任務各 1 枚 ＋ 初級全完成 1 枚 ＋ 超級全完成 2 枚
＋ 實戰家**過一關 1 枚、一天最多 3 枚**（`STAGE_CAP`）＋ 比快挑戰（答對 10 題）每天 1 枚
＋ **補氣站**那一場全部答對每天 1 枚
= **一天最多 14 枚**（攤子 9 ＋ 攤子以外 5）。
補氣站那一枚**只有「今天真的有題目可以補」的日子才算得到**，所以沒有錯題的日子上限還是 13 枚。

實戰家的規則原本分成「第一次過關全對 2 枚／不全對 1 枚，一天上限 2 枚」和「重玩過關 1 枚，一天上限 1 枚」
兩套，結果是：小孩第一關全對就把首次通關的額度用光，接下來**一關一關往下打反而一枚都拿不到**，
而回頭重玩舊關卡卻有 1 枚——跟說明寫的「還沒過的那幾關給比較多」正好相反。
現在只剩一條規則：**過關就是 1 枚，不管第幾關、第幾次，一天滿 3 枚為止**。
總量沒變，所以轉蛋的節奏一樣；差別是這條規則七歲講得出來，而且跟畫面上寫的一致。
攤子以外那幾枚由 `playCoinsLeft()` 一個函式算，首頁氣球和關卡頁都讀它，不各算各的。
**剛好把今天的金幣領完的那一刻**會跳一個視窗說「今天的金幣拿完囉」，
免得小孩以為是程式壞掉；遊戲還是可以繼續玩，隔天金幣會重新長出來。
完整規則寫在金幣圖示的說明視窗裡（實戰家頁面那行字旁邊的「?」也會打開同一個）。
那份清單是**寫給七歲小孩看的**：一句一件事、不講上限數字、不用「首次通關」「重玩」這種詞，
只講「去哪裡拿」。每天幾枚、誰有上限這些細節，交給下面那行動態的
「今天還能拿 N 枚」和給大人的小字（小字裡才寫一天最多 14 枚）。
**攤子以外的金幣沒有做進攤子任務裡**：攤子是「做完去領」的清單，實戰家和比快是過關當下自動入帳，
混在一起小孩會去攤子找領取按鈕。改成寫在首頁「乘法實戰家」那顆氣球的副標上
（有剩才顯示「今天還有 N 枚」），小孩不讀說明，但看得到符號。
**金幣記號一次只掛一顆**：掛在「下一個還沒過的關卡」，而且今天的 3 枚沒用完才掛
（比快挑戰那張卡同理，今天那一枚還在才掛）。12 關全掛就是騙人，一顆都不掛小孩又找不到
——2026-11-24 真的發生了，小孩在實戰家裡找不到金幣在哪。黃色底色仍然只代表
「這一關還沒過」的事實，不是金幣的承諾。
最上面那行字也從「今天還能拿 N 枚」改成**直接指路**（`coinHintHere()`）：
「有金幣記號的那一關，過關就有 1 枚金幣！」；過關額度用完就改指比快挑戰；
全部拿完才說「明天會再長出來」。旁邊的「?」打開的是 `INFO.here`，
**只講這一頁、最多兩句**，不再把全站的金幣規則倒一遍（`INFO.coin` 留給右上角的金幣圖示）。
`INFO.coin` 裡**補氣站那一條只有「今天真的有題目要補」才列出來** ——
不然小孩在實戰家按問號，會看到一個今天根本不存在的關卡。

### 金幣要小孩自己按一下才入帳

結果畫面原本直接寫「拿到 1 枚金幣」，小孩少了「自己拿到」的那一下。
現在那裡是一顆會上下浮動的按鈕 **「按我拿金幣！」**（`data-act="getcoin"`）：
按下去才響 `sfx.coin()`、才有三枚金幣飛到右上角、右上角的數字才跳上來，
而且**金幣是這個時候才真的加進存檔的**。

`finishStage()` / `finishTimed()` / `finishPump()` 只決定「這一場值不值一枚」，
把它放進 `game.result.coins`，再用 `game.result.pend`（`'stage'｜'timed'｜'pump'`）
記下該扣哪一個每日額度。真正入帳、扣額度、`save()`、`checkQuests()`、`coinDoneCheck()`
全部在 `takeCoin()` 裡。每日上限在 `takeCoin()` **再檢查一次**，
因為結果畫面可以擺著不按、跑去玩下一關、回頭再按。

**代價講清楚：沒按就離開＝那一枚今天就沒有了**（額度也不會被扣掉，所以下一關還是拿得到）。
這是使用者明確要的——他要小孩有「自己把金幣拿起來」的動作。
`r8.html` 盯著：按之前存檔沒變、按了才變、按過不能再按、沒按就離開不會自己入帳、額度滿了按了也不給。

**彩虹貪食蛇的金幣改成「吃到第二條彩虹」才算**（`{type:'snake', target:2}`）。
原本吃到第 7 個（一條彩虹）就跳「可以拿金幣了」，但畫面上寫的是「吃到 14 個放煙火過關」，
小孩領完金幣就離開，根本沒看到煙火——兩邊打架。
現在任務、過關、煙火、金幣是同一條線：**14 個答案＝兩條彩虹＝過關＝金幣**。
難度沒有變重：散步模式是自己走、照順序出題、5 顆心，14 題照口訣順序出。
一天的總量也沒變。

**玩完以後金幣在哪裡拿**，是實測時小孩第一個卡住的地方（攤子要回首頁點才領得到）。
所以結果畫面在有東西可領的時候會多一條 `.getcoin`：「攤子有金幣可以拿了，回首頁點它」，
跟旁邊那顆「去拿金幣」按鈕成對。沒有可領的時候整條不長出來。

## 畫廊可以自己整理

畫廊標題寫 `N/60`（`MAX_ART`），右邊有「整理」。
進整理模式以後每張畫下面長出 ← → 和垃圾桶：← → 換位置（頭尾那顆會 disabled），
垃圾桶**一定先跳確認視窗**：「要刪掉嗎？」＋「『小公園・3 的乘法』刪掉就沒有了喔。」
寫清楚是哪一張，但一句話講完（原本是「要刪掉這張畫嗎？」＋「刪掉以後就找不回來了喔」，
對六歲來說兩句都太長）。預設拿到焦點的是「不要刪」。離開畫廊（`go()` 裡 `name!=='gallery'`）就自動收起整理模式。

畫本身是**程式即時畫出來的**，不是檔案：17 個場景 × 9 種乘法表（2~9 ＋綜合），
再加上一顆亂數種子決定東西擺哪裡，所以「總共幾張」沒有上限，
畫廊只是最多收 60 張（超過就擠掉最舊的）。
即時畫不花任何成本 —— 全部是瀏覽器本機算的，沒有呼叫任何 AI 或伺服器。

貼紙要花 3 枚金幣轉蛋才抽得到，如果場景裡到處都是，收集就不值錢了。
`ART` 這張表同時給貼紙和場景用，所以很容易不小心共用 —— `r5.html` 會把每個場景的

## 同一張畫不要一直重複出現

原本是 `rnd(SCENES.length)` 純隨機。8 個場景的時候：

- 下一張跟上一張一樣的機率 **12.5%**
- 連玩 3 張，其中有兩張同場景的機率 **34%**
- 連玩 5 張，**79%**

小孩一個下午玩四五張，撞到同一個場景幾乎是必然的。

現在改成 `pickScene()`：先把**最近 5 次開過的**場景和**畫廊最新 3 張**的場景排除掉，
剩下的才均勻抽（真的全被排除才退回全選，防呆用）。
畫廊那部分是從存檔讀的，所以**重新整理、隔天再玩也記得**。

場景 8 → 17 再加上這條規則，連續 6 張以內**不可能**重複；`r5.html` 連抽 8 次驗這件事。
（場景一樣也不等於畫一樣 —— 道具位置和藏數字的位置還有另一顆種子 `k`，每次都不同。）

## 補氣站

答錯過的題目，**隔天**會變成一顆漏氣的熱氣球，到補氣站重新練。
重點是「隔一天再回想一次」，不是當天馬上重答 —— 當天重答靠的是短期記憶，隔天才看得出有沒有真的記住。

### 哪些題目會進去

掛在 `record(a,b,ok)` 上，答錯就呼叫 `pumpAdd(a,b)`。
**全站所有有對錯的遊戲都走這一個函式**（12 個呼叫點），所以不用一個一個遊戲去改；
乘法翻翻樂沒有作答、整支不呼叫 `record`，所以自動不算。

- 當天**答錯過一次就進去**，就算同一回合後來答對了也一樣。
- **以算式為單位，7×8 和 8×7 分開算**。（熟練度的 `key()` 會把兩者併成同一題，補氣站**不**正規化。）
- 同一題當天答錯很多次只會有一筆。

### 為什麼要另外存一份

熟練度 `m.facts[k]` 只記 `{c:答對幾次, w:答錯幾次, s:連續答對幾次}`，
**沒有日期**，而且 `key()` 把 5×3 和 3×5 併成同一題 —— 推不出「昨天答錯了哪幾題」。
所以補氣站自己存一份 `m.pump`，但**只存日期和補氣進度，不重複記熟練度的那三個數字**：

```js
m.pump = [{ a:7, b:8, d:'2026-11-23', g:['2026-11-24'] }]
//            │          │              └ 已經在補氣站答對的日子（不重複）
//            │          └ 休息到這天為止，要大於這天才會出現
//            └ 原始順序，7×8 和 8×7 是兩筆
```

### 什麼時候出現

`pumpDue()` 有兩個條件，兩個都要成立：

1. `x.d < 今天` —— 加入的當天不出現，隔天才出現。日期一律用 `todayStr()`（裝置本地日期）。
2. 今天還沒在補氣站答對過 —— 同一天答對多次只算一次，再出一次對進度沒幫助，
   只會讓「再玩一次」一直重複同一題。

一次最多出 `PUMP_N`（10）題，**最早加入的先出**（陣列順序就是加入順序）。

### 怎樣才算補好

**要在兩個不同的日子**（`PUMP_DAYS`）在補氣站答對，才算補好、移出補氣站。

| 發生什麼 | 結果 |
|---|---|
| 補氣站答對（今天還沒答對過） | `g` 加上今天 |
| 補氣站答對（今天已經答對過） | 不動 |
| `g` 滿兩天 | 補好了，移出補氣站，放一顆補過的熱氣球飛走 |
| **補氣站答錯** | `g` 歸零、`d` 改成今天 → 明天再出現 |
| 其他遊戲答對 | **不算**補氣進度 |

答錯之後不會在同一回合重出（其他遊戲的錯題重練完全沒動）—— 這個遊戲的用意就是隔一天再想一次。

### 金幣

**那一場全部答對給 1 枚，一天一次**（`d.p.pumpCoins`）。答錯就沒有，當天可以重新挑戰。

`COIN_MAX_DAY` 從 13 變成 **14**。但補氣站那一枚**只有「今天真的有題目可以補」的日子才算**
（`pumpCoinLeft()`），否則首頁會顯示一枚今天永遠拿不到的金幣。
沒有錯題的日子上限還是 13。

### 畫面

- 首頁六顆氣球**下面**多一顆**粉紅色、橫跨整排、置中**的漏氣熱氣球，名牌寫「請幫我補氣 N 題！」。
  N 是**今天還可以補幾題**，補一題少一題；N 為 0 整顆球就不出現。
- 作答介面直接沿用乘法實戰家那套（`VIEWS.play` ＋ 數字鍵盤），只是規則不同，
  所以 `showHelp()` 另外給它 `HELP.pump`。
- 補好一題：「7×8 補好氣了！」＋「之前卡住的題目，現在記住了。」＋一顆有補丁的熱氣球淡入飛走。
  第一天答對只說「明天再補一次，這題就補好了。」—— **兩天都答對才叫補好**，文案不能說謊。
- **訪客模式不顯示**（`GUEST` 不留紀錄，`pumpAdd` 也直接 return）。

### 兩種新的熱氣球畫法

`balloon()` 多了兩個選項：

- `deflate:true` —— 球身壓扁、右上角咬掉一個破口、身上縫一塊補丁（首頁那顆）。
  壓扁只套在**裁切區和外框**上，裡面的符號才不會跟著變形。
- `patch:true` —— 形狀正常，只留補丁（補好一題時飛走的那顆）。

### 刻意沒有動的地方

- 現有遊戲的玩法、金幣、同一回合的錯題重練
- 熟練度的算法（`record()` 只多了一行 `if(!ok) pumpAdd(a,b)`）
- 攤子任務的內容（補氣站答對會計入「今天答對 N 題」，因為它跟別的遊戲一樣走 `submit()`）

## 解說句一律放在標題下面

小孩的視線是由上往下的，解說擺在畫面最底下等於沒寫。
所以全站的「怎麼玩」都併進標題下那塊 `helper()`：
畫廊、貪食蛇、配對消消樂、選乘法表、翻翻樂牌桌、實戰家都改過。
底下只留**狀態**，不留說明——例如貪食蛇的「最長紀錄」（沒有紀錄時整行不顯示）。
實戰家的「今天還能拿 N 枚金幣」也搬到上面（`.note.topnote`）。

**遊戲進行中的提示句也一樣**：尋寶的提示句從畫的下面搬到**畫的上面、1~9 的下面**；
貪食蛇的提示句從蛇的下面搬到**盤面上面、題目下面**。
答錯的時候眼睛都還黏在數字和蛇身上，提示寫在下面根本不會看到。
兩句都掛 `.note.gnote`，它**固定留兩行的高度**（`min-height:2.5em`）：
提示句從一行變兩行的時候，下面的畫和盤面**不會被往下推**（實測位移 0.0px）——
遊戲中途版面跳動比提示沒看到更糟。

## 文案的審定標準

玩家看得到的每一句話都要同時過六關：**簡短好讀六歲能懂、符合兒童心理學、成長型心態、
正向語言、沒有贅字贅句、標點正確**（給大人看的小字只免前五關，標點一樣要對）。
這一輪照這六條全站掃過一次，改掉的：

- **句號**：標題以外的敘述句全部補上 `。`。`HELP` / `INFO` 的 53 條說明清單、
  遊戲中的提示句、彈窗內文、toast 都算敘述句；
  **按鈕、標籤、貼紙和場景名稱、狀態列（「還剩 5 個答案」）、小夥伴的對話泡泡不加**。
- **「蒐集」全部改成「收集」**——「蒐」小孩不會唸，而且全站其他地方本來就寫「收集」。
- **拿掉預言結果的話**：成績最低那一檔的標題「再練習一下會更棒！」改成「你剛剛很認真！」。
  當下的歡呼（「太厲害了！」「答對了！」）留著，**對未來的保證**不留。
- **拿掉評價人的話**：「63 種貼紙全部收集完成，你好厲害！」→「63 種貼紙全部收集完成！」。
- **任務完成的灰框只講一件事**：原本是「初級任務完成：玩「尋寶遊戲」，完成 1 張畫！可以去拿金幣了」，
  那個框只停 2.6 秒，小孩讀不完。現在是「**初級任務完成，可以去拿金幣了！**」（15 字）——
  做到了什麼攤子上本來就寫著，不用在這裡重講一次。
- **補漏字**：實戰家結果頁的「（過關要 8）」→「（過關要 8 **題**）」。
- **數字寫法統一**：實戰家解說句的「十二關」改成「12 關」，跟說明清單一致。

`r4.html` 會掃 `HELP` / `INFO` 每一條的結尾標點，也會擋掉已經淘汰的用詞，改回去會測不過。

## 回首頁的那顆氣球

標題列左上角那顆小氣球（`.logo`）**本來就是回首頁鍵**（`data-act="logo"`、`aria-label="回首頁"`，
按下去除了回首頁還會順便問一次伺服器有沒有新版本，見上面那一節），
但窄螢幕（≤420px）會把「乘乘熱氣球」五個字藏起來，所以手機上它看起來只是一顆氣球。
**兩件事要同時解決：看不看得出來可以按、按不按得到。**

*看得出來*：氣球現在有一個**淺色圓底**（`--surface2` 底色 ＋ `--hair` 外框 ＋ `border-radius:999px`），
跟右上角那排按鈕（`.iconbtn`：換人、ㄅ/國、音效）是同一套長相。
六歲的小孩不讀字，但學得會「圓圓的、有底色的＝可以按」。
窄螢幕把「乘乘熱氣球」五個字藏起來之後，它就變成一顆圓鈕；寬螢幕是一顆藥丸。
**刻意不加文字說明** —— 手機上就是因為塞不下才把標題藏起來的，再塞一行小字只會更小更難讀。

*按得到*：用 `::after` 往外撐，上下各 4px；窄螢幕再往左撐 8px、**右邊只給 1px**
（撐多了會蓋到旁邊的「我教你玩」）。實測：

| 螢幕寬 | 可按範圍 | 離隔壁 |
|---|---|---|
| 320／360 | 47×50 | 3.0px |
| 375／390／414 | 47×50 | 4.0px |
| 768 | 120×46 | 8.0px |

`host.html` 每個寬度都在量這個，`r5.html` 另外盯著「底色、外框、圓角」還在不在。
（`::after` 撐出來的範圍不影響版面高度，所以標題列不會變高。）

## 給大人的說明

寫給家長的話有兩個地方，**長短不一樣、不要互相取代**：

| 地方 | 怎麼進去 | 寫什麼 |
|---|---|---|
| 「關於遊戲」整頁（`VIEWS.about`） | 頁尾的「關於遊戲」 | 完整版，五張卡片：關於乘乘熱氣球／遊玩重點提醒／怎麼把遊戲加到主畫面（iOS、Android 逐步）／紀錄存在哪裡／遇到問題怎麼辦 |
| 「挑戰者」頁下方那張卡片 | 右上角頭像 →「挑戰者」 | 三句的提醒版：固定用同一台裝置和瀏覽器、建議用平板、紀錄存在這台裝置 |

會留兩份，是因為**走到的路不一樣**：家長是在新增／切換孩子的時候才會進「挑戰者」頁，
那時候正好要提醒他「紀錄跟著這台裝置走」；而「關於遊戲」是從頁尾進去的，
通常是第一次看到這個遊戲、想知道這是誰做的時候。

**沒有備份／還原功能**（原本有「存成檔案」和「從檔案還原」，已經移除），
所以這兩個地方是僅有的、提醒家長紀錄會不見的地方。
「關於遊戲」那一頁會出現「備份」兩個字，但只出現在
**「加到主畫面不是備份，還是無法保證紀錄不會遺失」**這句提醒裡——
不要讓它讀起來像有備份功能（`r7.html` 盯著這件事）。

加到主畫面寫得這麼細，是因為 iOS 上 **Safari 和主畫面圖示的 localStorage 是分開的**：
已經在 Safari 玩過一陣子才加到主畫面，紀錄不會跟著過去。所以文案的第一句就是
「建議第一次玩之前就先加」，重點提醒那張卡片也再講一次。

### 「關於遊戲」那一頁

- 整頁都是**寫給大人看的長文**：`.about` 靠左、行高 1.8、字級 18px，
  跟給小孩的畫面（置中、大字、短句）刻意長得不一樣。
- 沒有標 `nozy`——跟「挑戰者」頁那張卡片一致，注音模式打開時它也會上注音
  （孩子自己點進來至少讀得出字）。所以**改這一頁的字一樣要重建注音字型**。
- 「一」「不」的變調走 `zhuyin.txt` 的 `[詞]` 區：這一頁陸續補了
  `不再`、`一台`、`一段`、`一頁`、`不受` 這些詞（`一台` 是順手補的，
  「挑戰者」頁的「同一台裝置」本來就標錯）。
  另外兩個多音字是整站都會用到的：`重新`（預設讀 ㄓㄨㄥˋ，
  存檔失敗那個彈窗的「重新整理」本來就標錯）和 `應用`（預設讀 ㄧㄥ）。
- Instagram 連結有兩顆：第一張卡片的「利利」和最後一張的「利利寫生活」。
  **頁尾的「利利寫生活」已經改成純文字**，IG 只從這一頁進去，頁尾只剩「關於遊戲」一顆按鈕。
- 連結長相是**米色底**，
  引號包在底色裡面、沒有外框——有引號又有虛線框會變成兩層框，很擠。
  手指範圍一樣用 `::after{inset:-9px -4px}` 往外撐，不影響行高。
- 五張卡片共用 `.card.about`，中間的小標是 `h4`，安裝步驟用 `ol`、
  重點提醒用 `ul`（`list-style:none` + `::before{content:"・"}`，
  因為全站不用瀏覽器預設的圓點）。
- 第一張卡片句尾那顆熱氣球是 `balloon({pat:'pat-band',mini:true})`（跟標題列同一顆），
  class 叫 **`.abal` 不是 `.bal`** —— `.bal` 首頁的氣球在用，撞名會壞版面。
  顏色一定要寫在 `style` 裡（`balloon()` 讀 `--c1`~`--c3`），不寫就沒有顏色。
- 最後一行 `Have fun!` 加一朵雲，`.havefun` 置中。雲是 `ICON.cloud`，
  那句「修改最終決定權：我女兒」後面的笑臉是 `ICON.smile`，
  **兩個都是手繪 SVG，不是 emoji**（原稿寫的是 ☁️ 和 😃）。
- 右上角「我教你玩」在這一頁有自己的 `HELP.about`，不會掉回首頁那份說明。
- 玩到一半從頁尾按進來，會先跳「要離開嗎」的確認（跟「挑戰者」同一套 `askQuit()`），
  進度不會無聲無息不見。

## 更新的時候不要弄壞玩家的紀錄

紀錄存在瀏覽器的 `localStorage`，**跟著網址的 origin 走**（`https://slowlywithlili.github.io`），
跟檔案內容無關。所以改程式、改畫面、改圖、重新部署，**玩家的紀錄都不會動**。

會弄丟紀錄的只有這幾件事，改之前要特別小心：

| 動作 | 後果 |
|---|---|
| 改 `LS_KEY`（現在是 `mul99-adventure-v1`） | **所有人的紀錄立刻全部不見** |
| 換成自己的網域 | origin 變了，**所有人的紀錄不見**（舊網址的資料還在，但新網址讀不到） |
| 刪掉或改掉貼紙的 id，又沒在 `STICKER_OLD` 補對照 | 那幾張貼紙從收藏裡消失，收集數字會掉 |
| 減少 `STAGES` 的關卡數 | 超出範圍的過關紀錄會被 `fixStages` 丟掉 |
| 調低 `MAX_PLAYERS` | 超過的挑戰者會被 `migrate` 砍掉 |

**加東西是安全的**：新貼紙接在 `STICKERS` 後面、新遊戲、新任務、改文案、改圖，
都不會影響既有欄位。`fixPlayer`／`fixOwned`／`fixStages` 走的是白名單，
不認得的欄位會被忽略，不會讓整份存檔壞掉。

`localStorage` 是**整個 origin 共用**的，所以同一個 GitHub Pages 帳號下的其他專案
會跟這個遊戲共用同一個儲存空間。各專案的 key 一定要帶自己的前綴（這裡是 `mul99-`），
不然會互相覆蓋。

## 搜尋引擎

`index.html` 的 `<head>` 裡有 `description`、Open Graph、Twitter Card、`canonical`
和 JSON-LD（`VideoGame` 結構化資料）。根目錄有 `robots.txt` 和 `sitemap.xml`。
分享到 LINE/Facebook 時顯示的預覽圖是 `og.png`（1200×630，用 `og.html` 的版型截圖產生）。

**這些只是讓 Google 讀得懂，不會自動帶來排名。** 實際要被搜到，還是得去
[Google Search Console](https://search.google.com/search-console) 驗證網站並送出 sitemap，
再從別的地方（Instagram、部落格、社團）連過來。

## 進度儲存

所有挑戰者的進度存在瀏覽器的 `localStorage`（key：`mul99-adventure-v1`），換瀏覽器或清除資料會重來。
舊版（還沒有挑戰者功能）的存檔會自動變成第一位挑戰者「挑戰者 1」，進度不會不見。
「台灣小旅行」縮成「台灣景點」三張時，留下來的三張**沿用原本的編號**（`t6`/`t8`/`t10`），
搬家的兩張也有對照（曬柿餅 `t1`→`d4` 柿餅、鹿野高台熱氣球 `t9`→`v5` 渡輪）。
舊版「奇幻宇宙」那一類貼紙改成「恐龍時代」時同樣是**沿用同一組編號**（`m1`~`m10` → `n1`~`n10`），
所以已經收集到的張數不會歸零，陪玩中的夥伴也會跟著搬過去；
萬一搬過去的貼紙落在還沒解鎖的分類，那一類會直接幫他打開，收到的東西不會看不見。

程式內部還是有一個自動的備份槽（`localStorage` 的 `-bak` 鍵），
主檔壞掉或讀成空的時候會自動改讀它，這是防呆，使用者看不到也不用管。
判斷「主檔是好的」不只看 `players` 陣列不空，裡面至少要有一筆看得出是真人的紀錄
（合法的 `id` 或有名字）；不然 `{"players":[{}]}` 這種壞掉但格式正確的主檔會被當成好的，
開場的 `ensureDaily()` 一存檔就把好的備份也蓋掉了。

**存不進去的時候會講。** `localStorage` 寫入失敗（空間滿了）以前是默默吞掉的，
小孩會以為金幣有拿到。現在主檔寫失敗就不動備份檔（留住上一份好的），
並且跳一次提示請大人清空間。

**同一個瀏覽器開兩個分頁**時，舊的那個分頁手上是過期的 `state`，
只要它存一次檔就會把另一個分頁的進度整個蓋回去（連切換分頁都會觸發，
因為 `visibilitychange` 會呼叫 `save()`）。
現在監聽 `storage` 事件：發現別的分頁存了更新的紀錄，就在回首頁或分頁重新切回來時自動接手，
玩到一半則先記著不打斷。**注意：兩個分頁同時在玩**仍然是後存的覆蓋前存的，
沒有做欄位級合併——實務上不會發生（一台裝置一個小孩），但要知道有這個邊界。

說明視窗（`.modal`）用 `display:flex` + `.sheet{margin:auto}`，內容短就置中、
內容長就從上面開始而且**整個視窗捲得動**。
原本用 `display:grid; place-items:center`，說明一長就會上下都被切掉，
最下面那顆「知道了」永遠按不到，整個畫面卡住——矮螢幕（橫放的手機）尤其明顯。

讀取存檔時一律做白名單驗證（頭貼、貼紙 id、題目鍵、日期格式、關卡編號、數值上下限），
不合法的欄位會被丟掉或換成預設值 —— 同一個網域底下的其他頁面也能寫 `localStorage`，
所以存檔一律當成不可信的輸入處理。畫面上顯示的名字另外做 HTML 跳脫。
在 claude.ai 的 Artifact 環境中，會另外同步到帳號；一般網頁環境會自動略過這部分。
